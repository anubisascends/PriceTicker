# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A **Windows-only Adobe Premiere Pro video effect plugin** (`PriceTicker.aex`) written in C++ against
the After Effects–style effect API (`PF_*` / `EffectMain`) that Premiere hosts. It overlays a cumulative
running total of trading-card prices onto a clip, driven by timeline markers. See `README.md` for the
full user-facing workflow, parameters, and file formats.

## Build

There is no CLI build wrapper — it's an MSBuild solution.

```
msbuild Win/PriceTicker.sln /t:Build /p:Configuration=Debug /p:Platform=x64
```

- **`AE_SDK_BASE_PATH` must be set** (env var) to the After Effects SDK root, or the build fails at the
  PiPL step with `AE_SDK_BASE_PATH is not defined` before it ever compiles C++. The AE SDK supplies the
  effect headers (`AE_Effect.h`, `Param_Utils.h`, `AE_Macros.h`) and `PiPLTool.exe`.
- Premiere SDK defaults to `D:\source\SDK\Adobe\Premiere Pro` (override with `PREMIERE_SDK_PATH`).
- Output `.aex` lands in `_build\` (override with `PREMSDKBUILDPATH`). Toolset `v143`, VS 2022.
- Install by copying the `.aex` to `C:\Program Files\Adobe\Common\Plug-ins\7.0\MediaCore\`.

## Testing the SDK-free logic without the SDK

`CardData.cpp` / `CardData.h` deliberately have **no Adobe SDK dependency** (only `<cstdio>`, `<cstring>`,
`<cstdlib>`, `<cmath>`, `<cwchar>`). All CSV/marker parsing, the name→price join, timecode handling, and
currency formatting live there and can be compiled and run standalone — the practical way to verify a
change when the AE SDK (and thus a full build) isn't available:

```
cmd /c "call \"<vcvars64.bat>\" >nul && cl /nologo /EHsc /I . test_carddata.cpp CardData.cpp && test_carddata.exe"
```

Write a small `main()` that calls `PT_LoadCardsFromCsv` + `PT_LoadMarkersFromCsv` on real CSV files and
prints `PT_RevealSeconds` / `PT_TotalAtSeconds` results. Run it from the directory holding the CSVs
(paths passed to the loaders are resolved against the process CWD). There is no test framework in-repo.

## Architecture

Data flows: **two CSV files → parsed + joined into a flat store → rendered per frame as a text overlay.**

- **`PriceTicker.cpp`** — the effect entry point (`EffectMain` dispatches `PF_Cmd_*`). Owns param setup,
  the two file-picker buttons (`PF_Cmd_USER_CHANGED_PARAM`), sequence-data lifecycle, and `Render`.
- **`CardData.h/.cpp`** — the SDK-independent core: `PT_CardStore` (the flat POD store), parsers, join,
  and the time→total math. This is where correctness lives; keep it SDK-free so it stays testable.
- **`TextRenderer.h/.cpp`** — `PT_RenderText`: rasterizes one string to a premultiplied-BGRA bitmap via
  DirectWrite/Direct2D/WIC. Byte order matches `PrPixelFormat_BGRA_4444_32f` so it composites with no
  color conversion. It exposes `originX/originY` (internal padding) so callers can anchor the ink corner.
- **`PriceTicker.r` / `.rc` / `.rcp`** — the PiPL resource. `.rcp` is generated by `PiPLTool` at build.

### Host and rendering model

- The effect **only renders in Premiere** (`in_data->appl_id == 'PrMr'`); every other host passes the
  frame through unchanged. Assume Premiere for all render logic.
- Render copies the source frame, then composites the overlay as **two separately-colored single-color
  lines** (`DrawLine` helper): the `Total: $X` line, and the `+$value  Name` reveal line stacked directly
  below it. The text's **top-left ink corner** is anchored at (Position X, Position Y) so the total line
  never shifts when the reveal line appears/disappears. Font size is scaled by `downsample_y` for previews.

### The Premiere marker constraint (central design driver)

An effect hosted in Premiere **cannot read timeline markers and cannot create keyframes** — both require
the After Effects AEGP API, which Premiere does not expose to effects. Consequently:

- The reveal schedule is **imported as a file**, not read live. Markers (name + time) are exported from
  Premiere and loaded via the *Choose Markers…* button, then joined to the price CSV **by name**
  (case-insensitive). Order in the CSV is irrelevant; unmatched marker names render with `(?)` and `$0`.
- At render time, `current_time` is converted to seconds (`current_time / time_scale`) and `PT_TotalAtSeconds`
  sums every reveal at/before it — an `O(markers)` scan, no per-frame parameter sampling and no keyframes.
- `current_time` is **clip-relative**; Premiere's native "Export Markers" writes **sequence-time**
  timecodes, so the **Marker Time Offset** param subtracts the clip's sequence-start when needed.
- Marker times accept plain seconds, `H:M:S`, or `HH:MM:SS:FF`. Timecode **frames are kept separate**
  (`PT_Reveal.frames`) and converted to seconds at render using the live frame rate (`time_scale/time_step`),
  since the frame rate isn't known at load time.

## Conventions and gotchas when editing

- **`PT_CardStore` is memcpy'd into a Premiere sequence-data handle** and persisted with the project. It
  must stay a flat POD (fixed arrays, no pointers). **Bump `PT_CARDSTORE_VERSION` whenever its layout
  changes** — `SequenceResetup`/`Flatten` only copy the bytes when the stored version matches, else they
  re-init and reload from the saved file paths.
- **Adding/removing a param touches four places in lockstep:** the `PT_*` index enum and the `*_DISK_ID`
  enum in `PriceTicker.h`, and the matching `PF_ADD_*` call **in the same order** in `ParamsSetup`
  (`PriceTicker.cpp`). Disk IDs must be unique and stable across versions; param *reads* use the enum name
  so they're position-independent, but the `PF_ADD_*` order must equal the enum order.
- **PiPL out-flags must match:** `AE_Effect_Global_OutFlags` in `PriceTicker.r` (currently `0x50`) must
  equal what `GlobalSetup` sets in its `out_flags`. Reconcile both if you change the flags.
- **CSV parsing is quote-aware** (`pt_split_csv`) so names containing commas (`"Yorion, Sky Nomad"`) work
  in both the price CSV and the marker file. Reuse it rather than splitting on the first comma.
